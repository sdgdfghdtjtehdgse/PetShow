# Отчёт: программа PetShow и внесённые в неё ошибки

## 1. Описание программы

**PetShow** — веб-приложение для организации и посещения выставок домашних животных. Оно написано на **ASP.NET Core 8 (MVC + Razor Pages)**. Данные хранятся в **MySQL** (Entity Framework Core + Pomelo). Регистрацию и роли обеспечивает **ASP.NET Core Identity**.

### Модульная структура

| Модуль | Назначение |
|---|---|
| `Program.cs` | Точка входа: подключение БД, Identity, MVC, конвейер middleware, маршруты |
| `Models/` | Сущности: `ApplicationUser`, `Pet`, `Show`, `Venue`, `Booking`, `Ranking`, `Review`, `ShowQuestionnaire`, `Post`, `Comment`, `PostLike`, `CommentLike` |
| `Data/AppDbContext.cs` | Контекст EF Core: таблицы, уникальные индексы, правила каскадного удаления |
| `Data/SeedData.cs` | Начальные данные: роли `Admin`, `Organizer`, `User` и учётная запись администратора |
| `Migrations/` | Миграции схемы БД |
| `Controllers/` | Бизнес-логика (см. ниже) |
| `Areas/Identity/Pages/Account/` | Страницы входа, выхода и регистрации |
| `Views/`, `wwwroot/` | Razor-представления, CSS/JS, Bootstrap и jQuery |

### Контроллеры

- **HomeController** — главная страница, показывает 3 ближайшие выставки.
- **ShowController** — каталог выставок с фильтрами (тема, животное, город) и страница выставки.
- **BookingController** — бронирование участия питомца в выставке, список броней, отмена брони.
- **QuestionnaireController** — анкеты участников выставок.
- **ReviewController** — отзывы о площадках (рейтинг 1–5).
- **RankingsController** — результаты выставок, награды по категориям.
- **ProfileController** — профиль пользователя и управление питомцами.
- **CommunityController** — сообщество: посты, комментарии, лайки.
- **OrganizerController** — управление собственными выставками (роли `Organizer`, `Admin`).
- **AdminController** — админ-панель: места, выставки, брони, рейтинги, анкеты, пользователи и роли, отзывы, питомцы, модерация постов.

### Роли

`Admin` — полный доступ. `Organizer` — создаёт и редактирует свои выставки. `User` — обычный пользователь.

## 2. Внесённые ошибки (12 штук)

Проект в среде сессии не собирался: там нет .NET SDK. Правки сверялись вручную. Ошибки не помечены комментариями в коде, чтобы их можно было искать самостоятельно.

### Ошибки компиляции (3) — проект не соберётся

| № | Файл : строка | Что изменено | Последствие |
|---|---|---|---|
| 1 | `Models/Booking.cs:15` | Значение по умолчанию свойства `Status` типа `BookingStatus` заменено на строку `"Pending"` вместо `BookingStatus.Pending` | Ошибка CS0029: нельзя неявно преобразовать `string` в `BookingStatus` |
| 2 | `Controllers/RankingsController.cs:49` | Сортировка по несуществующему свойству `r.Place` вместо `r.Position` | Ошибка CS1061: в `Ranking` нет члена `Place` |
| 3 | `Controllers/OrganizerController.cs:146` | В `GetOwnedShow` убран `await` перед `_db.Shows.FindAsync(id)` | Ошибка CS1061/CS0029: `show` становится `ValueTask<Show?>`, а не `Show`. Обращение `show.OrganizerId` и `return show` не компилируются |

### Логические ошибки и ошибки времени выполнения (9)

| № | Файл : строка | Что изменено | Последствие |
|---|---|---|---|
| 4 | `Program.cs:55–56` | Порядок middleware: `UseAuthorization()` теперь стоит **перед** `UseAuthentication()` | Пользователь ещё не определён при проверке прав. Все страницы с `[Authorize]` (бронирование, профиль, админка и т. д.) перенаправляют на вход, даже если пользователь вошёл |
| 5 | `Data/SeedData.cs:14` | Из массива ролей убрана роль `"User"` | Роль не создаётся. При регистрации `AddToRoleAsync(user, "User")` возвращает неуспешный результат (исключения нет), и новые пользователи остаются без роли |
| 6 | `Data/AppDbContext.cs:40` | Уникальный индекс рейтингов был `{ShowId, Category, Position}`, стал `{ShowId, Position}` | Одно и то же место нельзя присудить в двух категориях одной выставки (например, «1 место» в «Самый умный» и в «Самый пушистый») — ошибка уникальности при сохранении |
| 7 | `Data/AppDbContext.cs:48` | Связь `Comment → Post`: `DeleteBehavior.Cascade` заменено на `Restrict` | Пост с комментариями невозможно удалить: нарушение внешнего ключа (и у автора, и у админа). Это противоречит комментарию в коде о каскадном удалении |
| 8 | `Controllers/BookingController.cs:68` | Проверка вместимости: `confirmedCount >= MaxParticipants` стало `>` | Ошибка на единицу: на выставку записывается на одного участника больше лимита |
| 9 | `Controllers/BookingController.cs:123` | В `Cancel` убрано условие `b.UserId == userId` | Любой авторизованный пользователь может отменить чужое бронирование, подставив его `id` (дыра в безопасности, IDOR) |
| 10 | `Controllers/ReviewController.cs:83` | Проверка прав: `&&` заменено на `\|\|` (`review.UserId != userId \|\| !isAdmin`) | Удалить отзыв может только администратор, который при этом сам его автор. Обычный автор не может удалить свой отзыв, а админ — чужой. Хотя по задумке удалять могут автор и админ |
| 11 | `Controllers/HomeController.cs:21` | Фильтр главной страницы: `StartDate >= UtcNow` стало `<=` | Вместо трёх ближайших выставок показываются уже прошедшие (сортировка по возрастанию даты даёт самые старые) |
| 12 | `Controllers/AdminController.cs:313` | Защита от самоудаления: `userId == currentUserId` стало `!=` | Админ может удалить собственную учётную запись, но не может удалить других пользователей — логика инвертирована |

## 3. Как проверить

1. Установите .NET 8 SDK и выполните `dotnet build`. Компилятор укажет на ошибки №1–3.
2. Исправьте их и запустите приложение. Ошибки №4–12 проявятся при работе: вход и авторизация (4, 5), создание рейтингов и удаление постов (6, 7), бронирование (8, 9), отзывы (10), главная страница (11), админ-панель (12).
3. Исходное состояние кода — коммит `cf64f48` (`git diff cf64f48` покажет все 12 правок).
